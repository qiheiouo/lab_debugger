# 逐来源解析配置

Lab Debugger 0.19 允许每个本地字节流使用独立的 CSV 字段或二进制 JSON 协议。串口与网络数据不再被迫共享同一解析方式，例如可以同时让 `serial:COM5` 使用 STM32 二进制帧，让 `udp:127.0.0.1:9000` 使用 `temperature,voltage` CSV。

## 配置方式

“协议解析”页顶部的“配置目标”包含：

- “全部本地字节流（默认）”：没有独立配置的数据源继承此配置；
- 已连接或曾配置的数据源，例如 `serial:COM5`、`udp:127.0.0.1:9000`；
- 带“独立 CSV”或“独立协议”后缀的来源：表示它不再继承默认配置。

选择目标后，可以：

1. 填写逗号分隔的字段并点击“应用 CSV 字段”；
2. 点击“加载 JSON 协议”，只给该来源启用二进制协议；
3. 点击“停用协议”，保留该来源的独立 CSV 配置；
4. 点击“恢复默认”，删除独立配置，重新继承全局默认。

CSV 最多 256 个字段，字段名必须非空、唯一、单行且不超过 1024 字节。协议文件最大 1 MiB，仍使用严格的 [JSON 协议格式](PROTOCOL_FORMAT.md)。无效配置不会替换当前有效配置。

## 数据隔离

解析器用完整 `sourceId` 选择配置，并为每个来源保存独立的半行、半帧和统计状态。输出字段继续使用 `sourceId.字段`，因此不同设备即使都发送 `speed`，也会形成不同曲线：

```text
serial:COM5.speed
udp:127.0.0.1:9000.speed
```

未配置的来源始终回退到默认解析器。删除某一来源的覆盖后，它会立即用默认配置创建新的解析状态，不会把旧协议残留字节拼进新数据。

## Session 与回放

开始记录时，每个串口或网络来源都会把“最终解析配置”冻结在自己的 `configuration/source_<index>.json` 中；即使它只是继承默认配置，也会保存解析后的完整结果。二进制协议原文保存在 `protocol/source_<index>_initial.json`。

Session metadata 使用 `source_parser_format: 1` 声明这一能力。回放会逐一核对：

- metadata 与来源配置的 `sourceId` 必须一致且唯一；
- 解析配置版本必须为 1；
- CSV 字段必须通过数量、长度和重复检查；
- 协议快照只能引用对应索引的固定路径，不能路径穿越；
- 声明存在的本地来源配置或协议文件缺失时必须拒绝回放，不能悄悄回退为错误解析器。

若 `metadata.json` 损坏、过大，或把 `replay_mode` 写成未知类型/模式，程序同样拒绝打开，避免原始 CDR 因路由信息丢失而进入默认 CSV 解析器。

旧 Session 没有 `source_parser_format` 时继续使用原来的全局 `protocol/initial.json` 或 `configuration/csv_fields.txt`，保持向后兼容。rosbag2 与 Remote Agent 的 CDR/结构化专用路由不经过本地 CSV/二进制解析配置。

为了保证原始记录与确定性回放一致，开始 Session 后默认和逐来源解析配置都会冻结；停止记录后才能更改。

## 当前边界

0.19 完成的是逐来源解析数据模型、界面、Session 快照和回放闭环。当前桌面 UI 仍各只有一个串口实例和一个网络实例；同时创建多个 COM 或多个 UDP/TCP 实例将在下一阶段建立在本配置模型之上。
