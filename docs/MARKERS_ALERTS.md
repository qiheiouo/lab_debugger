# Marker、阈值与运行健康告警

Lab Debugger 0.21 把人工操作说明、持续阈值和数据源运行健康告警放到同一条 Session 时间线中。实时曲线用黄色虚线显示手动 Marker、橙色虚线显示告警；事件同时出现在“Marker 与告警”页，并在记录时写入 `events.jsonl`。打开历史 Session 后，Marker 与告警会立即恢复，拖动或重新回放不会重复生成事件。

## 添加手动 Marker

连接任一实时数据源后，可以用两种方式添加：

1. 点击主工具栏的“添加 Marker”，输入例如“开始旋转测试”；
2. 打开“Marker 与告警”页，在“当前时刻说明”中输入内容并回车或点击按钮。

存在数值样本时，Marker 对齐到当前曲线的最新时间戳；尚无样本时使用本机当前时间。记录期间添加的 Marker 会写入当前 Session；未记录时只在当前实时界面显示。历史回放是只读的，不能向既有 Session 悄悄追加 Marker。

Marker 说明必须为单行非空 UTF-8 文本，最大 1024 字节。

## 配置阈值告警

每条规则包含：

- 规则名：时间线中用于识别规则的名称，必须唯一；
- 字段：曲线使用的完整字段名，例如 `serial:COM5.voltage`、`udp:127.0.0.1:9000.temperature`、`/imu.angular_velocity.x` 或派生字段 `power`；
- 条件：高于或低于；
- 阈值：越过此值时进入告警；
- 回差：告警复位所需的安全余量；
- 持续：必须连续越界的最短毫秒数；设为 0 时在首次越界样本立即触发；
- 说明：可选的处理提示。

例如高温规则为“高于 80，回差 5，持续 500 ms”：首次大于 80 时开始计时，后续样本确认连续越界满 500 ms 后产生告警；计时期间回到 80 或以下会取消本次计时。触发后持续处于高温不会重复刷屏；只有数值回到 75 或以下后，下一次越过 80 才会再次告警。低电压规则“低于 20，回差 1”则需要恢复到 21 或以上才会复位。

点击“应用告警规则”后，新样本会实时检查。基础字段和派生字段都可作为告警输入，匹配始终使用完整字段名，不会猜测或合并不同来源的同名字段。

## 配置运行健康告警

运行健康规则不检查某个数值，而是检查一个精确数据来源。每条规则包含唯一规则名、完整 `sourceId`、类型、窗口/超时和可选说明：

- `error_rate`（错误频率）：在滚动窗口内达到指定错误次数时触发。来源 I/O 错误以及二进制协议的垃圾、CRC、长度和解码异常都会计入；错误数降到阈值以下后自动复位。
- `inactivity`（无数据超时）：来源打开后，或 ROS2 Topic 成功订阅后开始计时；收到 RX 数据或 Topic 的 `SampleBatch` 时复位。超时只触发一次，新数据恢复后才允许再次触发。

常用来源 ID 示例：

- 串口：`serial:COM5`
- UDP：`udp:127.0.0.1:9000`
- TCP 客户端：`tcp-client:192.168.1.20:8000`
- Remote Agent 任意已订阅 Topic：`ros-agent:robot-a`
- ROS2 Topic：`ros-agent:robot-a:/imu`

来源断线本身不会取消超时监测，因此可以发现设备或网络掉线；从界面移除本地来源或取消最后一个同名 ROS2 Topic 订阅时才会解除对应监测。规则只做精确匹配，不会让一个设备的错误或数据替另一个设备复位。
如果同一 TCP 端点重连后报告了不同的 Agent ID，旧 Agent 及其 Topic 会立即解除布防，新身份只按自己的精确 `sourceId` 重新布防，避免遗留计时器产生错误身份告警。

## Session 与回放

开始记录时会同时：

- 清空旧的 Marker/告警显示；
- 清空所有告警的激活状态；
- 把当前规则冻结到 `configuration/alert_rules.json`；
- 把运行健康规则冻结到 `configuration/health_alert_rules.json`；
- 拒绝在记录中途修改规则，保证整段 Session 语义一致。

手动 Marker 使用 `category: "marker"`，阈值告警使用 `category: "alert"`。两者都保存在 `events.jsonl`，不会改变 `.ldraw` 原始格式、Remote Agent v1 线协议或 ROS2 Agent 版本。

回放会严格检查两份告警配置和事件日志：每份配置最大 1 MiB、最多 128 条规则，持续时间和健康窗口最长 24 小时；事件日志最大 64 MiB、单行最大 64 KiB、最多显示 10000 条 Marker/告警。未知版本、非有限阈值、负回差、非法来源、损坏 JSON 或超限内容都会明确拒绝，且不会替换打开前的有效配置。0.18~0.20 的阈值规则格式仍可读取，持续时间按 0 处理。

## 当前边界

当前尚未包括组合逻辑、系统声音/桌面通知、告警确认与消音流程。持续阈值只会在后续匹配样本证明越界时间已满足时触发，不会在完全没有新样本时猜测数值仍然越界；来源完全无数据的场景应使用 `inactivity` 规则。
