# Marker 与阈值告警

Lab Debugger 0.18 把人工操作说明和自动阈值告警放到同一条 Session 时间线中。实时曲线用黄色虚线显示手动 Marker、橙色虚线显示告警；事件同时出现在“Marker 与告警”页，并在记录时写入 `events.jsonl`。打开历史 Session 后，Marker 与告警会立即恢复，拖动或重新回放不会重复生成事件。

## 添加手动 Marker

连接任一实时数据源后，可以用两种方式添加：

1. 点击主工具栏的“添加 Marker”，输入例如“开始旋转测试”；
2. 打开“Marker 与告警”页，在“当前时刻说明”中输入内容并回车或点击按钮。

存在数值样本时，Marker 对齐到当前曲线的最新时间戳；尚无样本时使用本机当前时间。记录期间添加的 Marker 会写入当前 Session；未记录时只在当前实时界面显示。历史回放是只读的，不能向既有 Session 悄悄追加 Marker。

Marker 说明必须为单行非空 UTF-8 文本，最大 1024 字节。

## 配置阈值告警

每条规则包含：

- 规则名：时间线中用于识别规则的名称，必须唯一；
- 字段：曲线使用的完整字段名，例如 `serial:COM5.voltage`、`udp:127.0.0.1:9000.temperature`、`/imu.angular_velocity.x` 或派生字段 `power`；
- 条件：高于或低于；
- 阈值：越过此值时进入告警；
- 回差：告警复位所需的安全余量；
- 说明：可选的处理提示。

例如高温规则为“高于 80，回差 5”：数值第一次大于 80 时产生告警；持续处于高温不会重复刷屏；只有数值回到 75 或以下后，下一次越过 80 才会再次告警。低电压规则“低于 20，回差 1”则需要恢复到 21 或以上才会复位。

点击“应用告警规则”后，新样本会实时检查。基础字段和派生字段都可作为告警输入，匹配始终使用完整字段名，不会猜测或合并不同来源的同名字段。

## Session 与回放

开始记录时会同时：

- 清空旧的 Marker/告警显示；
- 清空所有告警的激活状态；
- 把当前规则冻结到 `configuration/alert_rules.json`；
- 拒绝在记录中途修改规则，保证整段 Session 语义一致。

手动 Marker 使用 `category: "marker"`，阈值告警使用 `category: "alert"`。两者都保存在 `events.jsonl`，不会改变 `.ldraw` 原始格式、Remote Agent v1 线协议或 ROS2 Agent 版本。

回放会严格检查告警配置和事件日志：配置最大 1 MiB、最多 128 条规则；事件日志最大 64 MiB、单行最大 64 KiB、最多显示 10000 条 Marker/告警。未知版本、非有限阈值、负回差、损坏 JSON 或超限内容都会明确拒绝，避免不可信 Session 消耗无限资源或产生错误告警。

## 当前边界

0.18 首先提供可靠的数值阈值、回差和时间线闭环，尚未包括持续时间条件、组合逻辑、CRC 错误率、Topic 超时、声音通知或确认/消音流程。这些能力会建立在同一事件模型上继续扩展，无需改变已有 Session 原始数据格式。
