# 多源时间对齐

Lab Debugger 0.22 为串口、TCP/UDP、Remote ROS Agent 和 Session 回放提供同一套逐来源时间策略。目标是让曲线、派生变量、Marker 和告警使用可解释的统一时间轴，同时保留原始证据，不修改任何设备或电脑的系统时钟。

## 四种策略

- `source`（原始源时间）：使用设备、数据源或 ROS Header 时间。普通串口/网络没有独立设备时钟时，其源时间就是桌面接收时刻。
- `receive`（电脑接收时间）：忽略源时间，使用 Lab Debugger 收到数据的本机时间。适合设备时间不可信、只关心到达顺序的场景。
- `manual`（手动偏移）：`有效时间 = 源时间 + offset_ns`。适合已知固定偏差的设备，安全范围为 ±7 天。
- `remote_clock`（ROS Agent 自动校正）：使用 Ping/Pong 最低 RTT 估计把 Agent 时间校正到桌面时间。没有有效估计时使用 Session 冻结的后备偏移；两者都没有时明确回退到未经校正的时间。

规则使用完整 `sourceId`。例如对 `ros-agent:robot-a` 设置自动校正，会覆盖 `ros-agent:robot-a:/imu` 等后代 Topic；若又给 `/imu` 的完整标识配置手动偏移，则更具体的规则优先。重复、空白、过长、含控制字符、未知模式或超范围配置都会整体拒绝，不会部分替换当前有效规则。

## 界面读数

“时间同步”页实时显示：

- 修正：实际加到源时间的偏移；
- 延迟：桌面接收时间减去对齐后的有效时间；它包含网络/调度影响，不等同于单纯网络 RTT；
- 不确定度：自动时钟估计的误差提示，当前约为 RTT/2；
- 样本/回退：观察数和无法应用目标策略的次数；
- 乱序：同一来源的有效时间向后跳变次数。

这些指标是诊断信息，不是硬实时或 PTP 精度承诺。跨互联网链路不对称时，Ping/Pong 偏移可能存在系统误差；高精度实验仍应使用 NTP/PTP、硬件触发或共同采样时钟。

## Session 语义

开始记录时，当前策略与 Agent 修正被冻结到 `configuration/time_alignment.json`，记录期间不可修改。`values.csv` 同时保存：

1. `timestamp_ns`：曲线、派生计算和告警使用的有效时间；
2. `source_timestamp_ns`：原始源时间；
3. `receive_timestamp_ns`：桌面接收时间。

原始 `.ldraw` 也继续保存源时间和接收时间。回放会先安全校验配置，再从原始双时间戳重建有效时间，因此无需相信旧的派生 CSV，也能得到可复核的时间轴。rosbag2 导入时 Header 时间优先作为源时间，bag 消息时间作为接收/调度依据；未知或无 Header 的消息使用 bag 时间。

## 建议流程

1. 先连接全部来源并观察几秒同步质量。
2. 普通本机串口/UDP 保持默认；只有明确知道时钟语义时才加偏移。
3. 跨机 ROS2 对 Agent 身份启用自动校正，确认没有持续回退或大量乱序。
4. 再开始 Session；策略会被冻结，避免一次实验中途改变时间定义。
5. 分析结果异常时同时检查有效、源和接收三个时间戳，而不是只看曲线。
