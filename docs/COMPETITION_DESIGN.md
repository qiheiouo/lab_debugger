# Lab Debugger AI 竞赛版软件设计说明

更新日期：2026-09-14

参赛方向：方向一——大模型与智能体应用赛道

参赛版本：`0.22.0-competition-ai`

开发分支：`competition/deepseek-analysis-2026`

## 一、作品简介

Lab Debugger AI 是面向机器人、嵌入式设备和实验室实验的跨平台数据调试工具。它能在一个桌面程序中同时接入串口、TCP、UDP 和远程 ROS2 Topic，将不同来源的数据解析为统一时间轴上的曲线，记录为可回放 Session，并结合 Marker、阈值告警、派生变量和 DeepSeek 大模型生成证据化诊断报告。

作品解决的核心问题不是“再做一个聊天窗口”，而是把调试过程中分散、异步、格式不同的大量数据，先由本地确定性程序整理成可核验的实验事实，再让大模型给出异常假设和下一轮验证步骤。用户可以从报告中的字段名、统计值和时间范围返回原曲线复核。

## 二、应用背景与需求

机器人和嵌入式实验常同时产生 MCU 串口、网络遥测、ROS2 传感器、里程计与控制命令。常见痛点包括：

- 工具分散，多来源时间不一致，异常出现时难以关联；
- 二进制协议、ROS2 CDR 和 CSV 的表达不同，人工整理成本高；
- 曲线能展示现象，却仍依赖有经验的工程师逐项提出排查步骤；
- 实验过程容易丢失上下文，事后难以重复、回放和说明结论依据。

本作品面向学生实验室、机器人战队、嵌入式研发和教学演示，要求实现：

1. 在 Windows 桌面统一采集、展示和记录多来源数据；
2. Windows 无需安装 ROS2，也能通过 Linux Agent 监听 ROS2 Topic；
3. 原始数据与结构化数值可追溯，回放结果稳定；
4. AI 只接收用户确认的有界摘要，输出可复核而非武断的诊断；
5. AI 网络失败时不影响采集、回放和人工分析。

## 三、总体设计

```text
物理设备 / ROS2 / 网络
   │
   ├─ 串口实例（可动态增删）
   ├─ TCP 客户端/服务端、UDP
   └─ ROS2 Humble Agent ── Remote Agent v1 ── Windows 客户端
   │
   ▼
SourceManager（来源生命周期、统计、隔离）
   │
   ▼
ProcessingPipeline（CSV / 二进制 / CDR 字段映射）
   │
   ├─ 时间对齐 ── 派生/滤波 ── Marker/告警 ── 实时曲线
   │
   ▼
Session（原始流、values.csv、events.jsonl、配置快照）
   │
   ├─ 确定性回放 / rosbag2 导入
   └─ 本地摘要器 ── 用户预览确认 ── DeepSeek API ── JSON 诊断报告
```

系统使用 C++20、CMake、Qt 6 和 SQLite。核心数据处理尽量保持与 GUI、ROS2 运行时解耦；Linux ROS2 Agent 使用 rclcpp 与通用类型支持，桌面端使用 TCP 协议接收 Topic 目录、结构化数值和原始 CDR。

## 四、功能模块

### 4.1 多来源采集

- 最多 16 个动态串口或网络来源；
- TCP 客户端、TCP 服务端、UDP 与串口；
- 每个来源具有独立解析状态、统计、发送目标和 Session 配置；
- 多来源数据不会拼接到同一个 CSV 半行或二进制帧。

### 4.2 ROS2 Topic 监听

Linux 端运行 `lab_debug_agent_node`，发现 ROS2 graph 并向桌面端发送 Topic 目录。用户在 Windows 端选择 Topic 后即可订阅。内置常见消息的字段映射，同时通过 introspection 支持可加载类型支持的自定义消息。结构化数值进入曲线，原始 CDR 进入原始记录，不会被误送入 CSV 解析器。

### 4.3 处理、时间轴与告警

- CSV 和带 CRC 的 JSON 二进制协议；
- 派生表达式、低通/高通、移动平均、微分、积分和角度展开；
- 源时间、接收时间、手动偏移和 Agent 自动时钟校正；
- Marker、阈值/持续阈值、错误率和无数据告警；
- 同名字段通过完整来源标识隔离。

### 4.4 Session 与回放

Session 保存来源元数据、解析配置、原始流、结构化数值与事件。回放恢复当时配置与事件，不重新生成历史告警；rosbag2 SQLite 可预检、选择 Topic 并导入。AI 功能以已经停止记录的 Session 为分析单位，不干预实时采集线程。

### 4.5 AI 智能诊断

摘要器最多扫描 200000 条数值，保留最多 48 个字段的计数、极值、均值、标准差、首末值、变化量和时间范围，并加入最多 50 条 Marker/告警/时钟事件。它不读取或上传原始字节流、原始 CDR 或完整 CSV。

用户可以在界面中：

1. 选择或沿用当前回放 Session；
2. 生成并查看本地 JSON 摘要；
3. 填写设备和实验背景；
4. 运行时粘贴 API Key、选择 Flash 或 Pro 模型；
5. 明确勾选同意后发送；
6. 查看并保存结构化中文诊断报告。

提示词要求报告包含总体判断、异常现象、证据、可能原因、验证步骤、置信度、风险和下一步行动，并在证据不足时明确说明。返回内容必须是 JSON 对象，否则程序拒绝把它显示为有效诊断报告。

## 五、创新点

1. **确定性证据与生成式分析分层。** 数值解析、时间对齐和统计由本地程序完成，大模型负责组织假设，减少把幻觉包装成测量事实的风险。
2. **跨来源可回放诊断。** 串口、网络和 ROS2 数据进入同一 Session，AI 的结论可以回到原始曲线、Marker 和告警复核。
3. **ROS2 与普通嵌入式调试统一。** Windows 用户无需本机 ROS2 环境，也能把机器人 Topic 与 MCU/网络数据放在一个工具中分析。
4. **可见的数据边界。** 用户在联网前能看到将发送的完整摘要；原始 CDR 和协议字节默认留在本机。
5. **低成本竞赛闭环。** 默认 Flash、关闭思考、限制 1400 输出 tokens、45 秒超时且不自动重试，适合低余额现场演示。

## 六、异常与降级设计

- Session 损坏、文件过大、字段超限或非有限数值会被明确拒绝或计数；
- API Key 只在运行时输入，不写入 Git、配置、安装包或 Session；
- 请求可取消，有超时和响应大小限制；
- HTTP/API 错误、余额不足、断网或非 JSON 返回会显示失败原因；
- AI 失败不会改变 Session，也不会阻塞原有采集与回放；
- 现场可展示一份提前保存并标明生成时间的真实报告，但不得冒充本次实时请求。

## 七、验证方案与当前结果

长期主线已持续进行 Windows/Linux 严格编译、Qt offscreen 测试以及 Ubuntu 22.04/ROS2 Humble 容器内真实 DDS/TCP 集成验证。竞赛新增永久测试覆盖：

- CSV 引号、精确时间戳、字段统计、事件提取和摘要大小限制；
- Bearer Header、请求路径、模型、JSON 输出、关闭思考与 token 用量；
- API Key 不进入 JSON 正文；
- 非本机明文 HTTP 被拒绝；
- AI 页面主要控件和主窗口接入。

自动测试使用本机模拟 API，不产生费用。提交前仍需完成一次参赛者 Key 的真实 API 冒烟测试、Windows 可见界面检查和便携包验收。

## 八、推荐现场演示

建议准备一段不含隐私的 ROS2 移动机器人 Session：同时记录 IMU、里程计、关节状态和控制命令，在直行、急转与外部扰动处加入 Marker，并设置角速度或速度偏差告警。

现场流程控制在 4 至 6 分钟：

1. 展示 Windows 客户端连接 Linux ROS2 Agent 并订阅 Topic；
2. 展示多来源曲线、时间同步、Marker 和告警；
3. 停止记录并打开 Session 回放；
4. 进入 AI 页生成摘要，说明原始数据未上传；
5. 调用 DeepSeek，选择一条结论回到曲线证据复核；
6. 关闭网络，说明 AI 失败不影响本地回放，并展示已保存的真实备用报告。

演示视频由参赛者自行录制，仓库不生成或伪造现场视频素材。

## 九、原创、依赖与 AI 使用声明建议

Lab Debugger 的软件架构、数据协议、采集处理链路、Session 格式、测试设计与集成实现由参赛团队完成。项目使用 Qt、CMake、SQLite、ROS2 等开源组件，最终提交材料应附对应许可证清单。

开发过程使用 Codex/ChatGPT 辅助需求整理、代码生成、代码审查、测试设计与文档撰写；参赛团队负责确定需求、选择方案、运行验证、处理真实设备数据并对最终作品负责。作品运行时使用 DeepSeek 官方 API 对程序生成的摘要进行诊断。提交时应按赛事要求如实标明 AI 辅助范围，不将 AI 生成内容冒充未经审核的人工事实。

## 十、版本边界与后续计划

竞赛代码只维护在 `competition/deepseek-analysis-2026`。稳定主线停留在 Lab Debugger 0.22，不因比赛引入网络模型依赖。比赛结束后可归档该分支；其中与 AI 无关且经过复核的通用改进，可再单独评估是否合并主线。

赛前剩余工作按优先级为：真实案例 Session、一次真实 API 测试、Windows 便携包、可见界面验收、作品简介与依赖清单定稿、演示视频和现场彩排。
