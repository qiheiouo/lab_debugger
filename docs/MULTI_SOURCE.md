# 多数据源使用说明

Lab Debugger 0.20 支持在一个桌面进程中同时使用多个串口和多个 TCP/UDP 端点。本地串口与网络实例合计最多 16 个，并可再连接一个 Remote ROS Agent。每个实例保留独立的连接状态、收发序号、CSV 半行、二进制半帧、解析配置、曲线和 Session 身份。

## 添加和管理实例

### 多串口

1. 打开左侧“串口”页，选择 COM 口和串口参数。
2. 点击“添加 / 连接”。实例会以 `serial:COM5` 一类完整标识出现在上方列表。
3. 更换 COM 口后再次添加；已有串口不会因此关闭。
4. 在列表选择具体实例后，可单独“断开”“重连”或“移除”。

同一个 COM 口只有一个稳定 `sourceId`。对相同 COM 再次点击“添加 / 连接”会更新并重开该实例；操作系统通常也不允许两个实例同时独占同一物理串口。

### 多网络端点

网络页同样先填写配置，再点击“添加 / 打开”。实例标识规则如下：

- TCP 客户端：`tcp-client:<远端主机>:<远端端口>`；
- TCP 服务端：`tcp-server:<绑定地址>:<本地端口>`；
- UDP：`udp:<绑定地址>:<本地端口>`。

TCP 客户端由远端端点区分；TCP 服务端和 UDP 由本地绑定端点区分，因为同一进程通常不能重复占用同一监听端口。对相同标识重新打开会更新原实例，而不是创建同名副本。

## 精确发送

发送区的“发送到”列出每个本地实例的完整 `sourceId`。发送前应明确选择目标；数据只会交给这一实例。目标暂时断开时仍保持原选择并返回发送失败，不会静默切换到另一台设备。Remote Agent 传输的是 ROS 订阅协议，不属于这个原始 ASCII/HEX 发送列表。

## 独立解析和曲线

“协议解析”页的“配置目标”可以选择默认配置或某一个具体 `sourceId`。例如：

- `serial:COM5` 使用 `examples/protocols/stm32_status.json`；
- `udp:127.0.0.1:9000` 使用 `temperature,voltage` CSV；
- 其他来源继续继承默认 CSV。

不同来源的半行和半帧不会拼接。同名字段会带来源前缀形成不同曲线，例如 `serial:COM5.speed` 与 `udp:127.0.0.1:9000.speed`。派生表达式可用反引号引用完整字段名。

## Session 冻结规则

点击“开始 Session 记录”时，程序只冻结当时处于已打开状态的来源，并为每个来源保存端点和最终解析配置。记录期间：

- 已声明来源可以断开并按原配置重连；
- 不能新增或移除来源；
- 不能修改已有来源的端点、串口参数或解析配置；
- 未在开始时声明的迟到来源不会写入该 Session。

停止记录后，列表管理和配置修改恢复。回放会按原完整 `sourceId` 恢复解析，原始数据不会跨来源合并。

## ROS2 Topic

ROS2 数据通过“ROS Agent”页连接 Linux 上的 `lab_debug_agent`。Windows 客户端收到 Topic 目录后可选择 topic/type、QoS 和队列深度进行订阅；常见消息及可 introspection 的自定义消息会直接生成结构化曲线，所有消息同时保留原始 CDR。原始 CDR 不会进入 CSV 解析器。当前桌面端支持一个 Remote Agent 连接，多 Agent 实例仍属于后续工作。
