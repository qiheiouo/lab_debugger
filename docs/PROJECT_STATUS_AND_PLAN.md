# 项目进度与后续计划

更新日期：2026-10-18
主线阶段版本：Lab Debugger 0.23

## 当前结论

Lab Debugger 已形成可独立运行的跨平台实验数据调试主链路：多串口/多网络/ROS2 Topic 采集，CSV 与二进制协议解析，实时与历史曲线，派生与滤波，Marker/告警，Session 记录/回放，以及 rosbag2 离线导入。0.23 完成了历史曲线、区间统计、CSV 导出，并开始记住常用连接参数和工作界面。比赛专用 AI 功能继续留在独立分支，不合并回主线。

项目定位是个人和小范围朋友使用的工具，不再以公开发行的成熟商品为默认目标。开发优先级是“常用功能好用、真实设备上能稳定工作”，而不是安装器、签名、自动升级、插件市场或公网服务安全体系。

按“能日常使用”而不是“所有设想都实现”衡量，当前估算如下：

| 维度 | 估算 | 说明 |
|---|---:|---|
| 核心数据链路 | 95% | 采集、解析、实时/历史曲线、导出、记录、回放、ROS2 和时间对齐已闭环 |
| 个人/小团队日常使用 | 93% | 剩余工作主要由真实设备使用中暴露的问题驱动 |
| 基础跨平台可用性 | 85% | Windows 桌面端和 Linux/ROS2 Agent 链路已建立，但不追求穷举系统组合 |
| 正式公开发布准备 | 40% | 有便携目录和工程质量基础，无签名、升级、安装器和运营配套；此项不再继续补齐 |

百分比用于排期，不代表质量评分。正式发布准备的 40% 主要来自已有的 CMake 安装/依赖部署、版本注入、日志、跨平台分层、自动测试和文档。安装器、代码签名、自动升级、崩溃上报、发布服务和公网安全审计并未完成，也不再列入当前目标。

## 已完成能力

- 最多 16 个本地串口/网络实例动态增删，来源、解析状态、统计和精确发送互相隔离；
- TCP 客户端/服务端、UDP、串口、Remote ROS Agent 并行采集；
- Windows 无需安装 ROS2 即可监听 Linux Agent 提供的 ROS2 Topic，常见消息及可 introspection 的自定义消息可进入曲线，原始 CDR 始终保留；
- CSV 与 JSON 二进制协议、CRC/流重同步、逐来源配置冻结；
- 安全派生表达式、滤波、微分、积分、角度展开；
- Marker、阈值/持续阈值、错误率和无数据告警；
- Session 原始流、数值、结构化帧、事件和配置快照，以及确定性回放；
- rosbag2 SQLite 分卷预检/筛选/导入和真实 CDR 映射；
- 源时间、接收时间、手动偏移、ROS Agent 自动时钟校正及同步质量诊断。
- 固定历史曲线拖动、滚轮缩放、区间框选统计，以及按勾选字段导出的完整精度 UTF-8 CSV。
- 记住窗口布局、页签和最近的串口/网络/ROS Agent 参数，但不在启动时自动连接外部设备。

## 主线仍待完成

以下内容只在真实使用需要时继续：

1. 用现有 STM32/串口和跨机器网络进行日常采集，修复实际暴露的断连、丢数或交互问题；
2. 如果长 Session 已经明显卡顿，再增加稀疏索引或磁盘级历史查询；
3. 只为实际使用链路补简短操作说明和可复用的小示例；
4. 组合告警、重采样、更多 Agent 等功能由具体使用需求决定。

安装器、插件市场、签名/升级服务、公网 TLS/认证、穷举跨平台组合和大型文档不是当前待办。Remote Agent 默认继续用于回环、可信局域网或 SSH/VPN 通道。

## 比赛分支归档边界

`competition/deepseek-analysis-2026` 从 0.22 稳定点分出，包含 DeepSeek 分析和比赛提交材料。用户已决定不再需要比赛功能，因此该分支只作为历史归档保留。`master` 不合并其 API、提示词、演示数据或比赛文档，继续保持离线可用、确定性处理和无云模型依赖。

若未来确实需要智能分析，应重新从当时的主线需求评审，而不是直接合并旧比赛分支。

## 下一步开发顺序

1. 用项目连接真实设备，记录操作中重复出现的不便或错误；
2. 每次选一个完整的小功能或一个可复现问题修复，完成后只跑相关构建和针对性测试；
3. 当实际数据量证明内存历史不够用时，再开发磁盘索引；
4. 保留 Linux 为主要开发/验证环境，只在改动 Windows 专属行为或较长时间未验证时进行 Windows 构建。
