# TCP/UDP 网络数据源

Lab Debugger 0.4 的网络适配器实现 `IDataSource`，因此网络数据与串口、回放共享 Terminal、协议解析、TimeSeries、Plot 和 Session 链路。Socket 的创建、收发、错误和关闭都运行在独立 `QThread`，GUI 只接收批量刷新事件。

## 模式

### TCP 客户端

填写远端主机和端口后点击“打开”。`open()` 表示异步连接请求已被接受；只有连接建立后状态才变为 Open，才允许发送。TCP 是字节流，单次 `readyRead` 不等于应用层的一帧，协议引擎负责处理半帧、粘包和重新同步。

### TCP 服务端

填写监听地址和本地端口。监听成功即进入 Open；没有客户端时发送会返回错误。当前只保留一个活动客户端，新客户端连接时会关闭并替换旧客户端，适合设备到调试器的一对一链路。

### UDP

填写本地绑定地址/端口及远端数字 IPv4/IPv6 地址/端口。每个收到的数据报形成一个独立 `DataChunk`，不会与相邻数据报拼接。发送时一个操作对应一个 UDP 数据报。

绑定地址可使用 `0.0.0.0` 或 `*` 监听所有 IPv4 接口。当前 UDP 远端不进行主机名解析；请直接填写数字 IP。

## 数据与时间语义

- RX 和 TX 都会进入终端与 Session 原始流；
- 普通网络 socket 没有设备时钟，因此 `sourceTimestamp` 和 `receiveTimestamp` 都取本机收到或接受发送的 Unix 纳秒时刻；
- 每个 `NetworkSource` 使用单调递增序号；
- `sourceId` 由模式和端点组成，例如 `tcp-client:127.0.0.1:9000`、`tcp-server:0.0.0.0:9000` 或 `udp:0.0.0.0:9000`；
- TCP 的 TX 事件表示 Qt socket 已接受相应字节进入发送缓冲，并不等同于远端业务层已经处理；
- UDP 的 TX 事件表示系统接受了该数据报。

## 与协议和 Session 配合

ASCII/HEX 发送入口通过“发送到”选择框明确路由到串口或网络。网络 RX 数据进入 CSV 或已加载的 JSON 二进制协议解析器，解析后的数值与串口数据一样进入曲线和统计。

串口、网络和 Remote Agent 可以同时连接。`SourceManager` 聚合各自统计并把原始数据送入同一个 Session；CSV 半行和二进制半帧缓存按 `sourceId` 隔离，即使不同来源的字节交错到达也不会互相拼接。同名数值字段以“`sourceId.字段`”形成不同曲线。

开始 Session 时会冻结当前已连接来源及其配置。记录期间可以断开并按相同配置重连这些已声明来源，但加入新来源或更改端点需要先停止记录。Session 会保留每个来源的配置、原始 RX/TX、解析结果和事件，之后可通过 `ReplaySource` 原样回放。

## 当前边界

- 当前 UI 提供一个 `NetworkSource` 实例；多个网络端点的动态增删界面尚未实现；
- 串口和网络当前共享一份 CSV 字段或二进制协议定义，解析状态独立，但尚不能为每个来源选择不同协议；
- TCP 服务端当前只管理一个活动客户端；
- 尚未加入自动退避重连、TLS、UDP 组播/广播专用配置；
- 尚未进行数小时网络压力测试和异常网络条件模拟。

本机自动测试已覆盖 TCP 客户端、TCP 服务端、UDP 的双向精确负载，以及 TX/RX 事件发布。
